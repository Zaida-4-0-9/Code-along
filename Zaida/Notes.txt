    Object Oriented Programing (OOP):

    The four main Pillers of OOP are:
        1. Encapsulation
        2. Abstraction
        3. Inheritance
        4. Polymorphism

    Encapsulation:
        the Idea of hiding the internal details of how an Object works and controling how data is accsesed or modified
        typicaly done through private and public properties and methods

        without Encapsulation:

            public class BankAccount
            {
                public double Balance; // Not ideal — can be changed freely from anywhere
            }

        With Encapsulation:
            public class BankAccount
            {
                private double _balance;

                public double Balance
            {
                get { return _balance; }
            }

            public void Deposit(double amount)
            {
                if (amount > 0)
                {
                    _balance += amount;
                }
            }
        }

        Now we're protecting the data no one outside the class can change _balance directly they must use the provided method which we can validate and control

    Abstraction:
        the Idea of only showing the esentials of an Object letting you interact with Complex things in a simple way
        we use Abstraction a lot and even me typing this is abstacted as I don't have to think about how the characters are getting stored to the computers memory

        Example Coffee Machine:
            public class CoffeeMachine
            {
            public void MakeCoffee()
            {
                HeatWater();
                Brew();
                Pour();
            }

            private void HeatWater() { /* internal details */ }
            private void Brew() { /* internal details */ }
            private void Pour() { /* internal details */ }
            }

            all we need to do is call MakeCoffee() we don't need to accsess the internals

    Inheritance:
        this is when you create a new class that is based on an existing one
        the new class (child) inherits things from the existing class (parent) and can add or overide behavior
        this helps you avoid code duplication and supports reusing the code

        Base Class:
            public class Animal
            {
                public string Name { get; set; }

                public void Eat()
                {
                    Console.WriteLine($"{Name} is eating.");
                }
            }

        Derived Class:
            public class Dog : Animal
            {
                public void Bark()
                {
                    Console.WriteLine($"{Name} says: Woof!");
                }
            }

        Using inheritance:
            Dog myDog = new Dog();
            myDog.Name = "Fido";
            myDog.Eat();  // Inherited from Animal
            myDog.Bark(); // Defined in Dog

    Polymorphism:
        Means "many forms"
        it allows you to treat different objects as if they are the same type while each still an indevidual

    putting it all together (Example):
        public abstract class Shape // Abstraction
            {
                public abstract double GetArea(); // Abstraction
            }

        public class Circle : Shape // Inheritance
            {
                private double _radius; // Encapsulation

                public Circle(double radius)
                    {
                    _radius = radius;
                    }

               public override double GetArea() // Polymorphism
               {
                   return Math.PI * _radius * _radius;
               }
            }

        public class Square : Shape // Inheritance
            {
                private double _side; // Encapsulation

                public Square(double side)
                    {
                        _side = side;
                    }

                public override double GetArea() // Polymorphism
                    {
                        return _side * _side;
                    }
            }

    using it:

        List<Shape> shapes = new List<Shape>
            {
                new Circle(5),
                new Square(4)
            };

        foreach (var shape in shapes)
            {
                Console.WriteLine($"Area: {shape.GetArea()}");
            }

    HTML:
        HTML pages are made up of the following parts:

            The Doctype, which for our purposes will always be HTML.
            The page or document is outlined by the <html> and </html> tags. All of the content for the page is within these tags. This tag also has a lang attribute whose value indicates the language that our content will be written in. Accordingly, we will use <html lang="en">.
            The head is contained within the <head> and </head> tags. Content within the head is (mostly) not displayed. This includes the title for the page between <title></title> tags (which is displayed in the tab displaying the webpage), the favicon that shows up on your browser tab (to the left of the title of the webpage), meta tags, and links to CSS and JavaScript files that the page uses. You will want to specify <meta charset="UTF-8"> to make sure our HTML displays properly on our webpage.
            The body is contained within the <body> and </body> tags. This is where the visible content of the page is and can be divided among the following tags if you so desire (these are more for organizing related content and could just be replaced with divs):
                <header></header>, useful to group introductory content like headings, logos, a search form, etc.; heading elements can be anywhere.
                <main></main>, where most of your content will go.
                <footer></footer>, for content that would be displayed at the bottom of the page, like copyright information and related links.

                The content of the page is made up of more elements, as well as content within elements. Common elements include the following:

                <img /> places an image on the page. Make sure to provide values for the four following attributes of the <img /> tag: 

                    src=”image.jpg” tells the browser which image to load.
                    alt=”description” gives the substitute text for the image that is used with assistive devices.
                    width=”” gives the width of the image.
                    height=”” gives the height of the image.

                When setting the width and height, the number inside the quotes is understood to be pixels- no further information is needed.
                Image Formats

                The perfect image would be high quality and would be a small file size.

                .gif does well at compressing large areas of a single color, but it only has a limited color space of 256 colors and is most popular for small, animated videos.

                .svg is good for logos and icons because it uses vector lines, and no illustration will get pixilated because it doesn’t use pixels.

                .jpg is great for photos by balancing quality and file size during compression.

                .png is for images that need transparency and is good at compression for photos and images. 

                Consider the size of the image, the file format, and compressing settings. You want your images to download as fast as possible.
                Responsive Images and Width

                If you want to load different images based on the size of the user's screen, you can specify the value of the "srcset" attribute of an <img /> tag as a comma-separated list of image names and intrinsic sizes (representing the actual size of the image using the unit "w"); in conjunction, you can specify the value of the "sizes" attribute as a comma-separated list of a media condition (for example, (min-width: 650px)) and slot size for the image to fill if the media condition is true. The following example renders image1.jpg with a width of 480px when the screen width is greater than 650px, image2 at a width of 300px when the screen width is less than 650px but greater than 465px, and image3 at a width of 200px for a screen width that's less than 465px. The alt text applies to whatever image ends up being rendered:

                <img
                srcset="image1.jpg 480w, image2.jpg 800w"
                sizes="(min-width: 650px) 480px, (min-width: 465px) 300px,
                        200px"
                src="image3.jpg"
                alt="Example Image" 
                />

                

                

                srcset=”comma-separated list of the different image copies by viewport width or image pixel width”
                Responsive Pictures

                Another approach to loading different images based on the size of the user's screen is to use the <picture> tag to enclose <source> tags and a fallback <img /> tag.  By providing each source tag with a value for the "media" attribute (for example, "(min-width:650px)") and the "scrset" attribute (for example, "image1.jpg"), you can have different images load for different screen sizes. The following example renders image1.jpg when the screen width is greater than 650px, image2 when the screen width is  less than 650px but greater than 465px, and image3 for a screen width that's less than 465px. The alt text applies to whatever image ends up being rendered:

                <picture>
                    <source media="(min-width:650px)" srcset="imgage1.jpg">
                    <source media="(min-width:465px)" srcset="image2.jpg">
                    <img src="image3" alt="Example Image" style="width:auto;">
                </picture>

            HTML Form Overview
                Before user information can be processed and saved in a database, it needs to be submitted. Before it can be submitted, it needs to be inputted. This is where html forms come in.

                In this page, you will:

                    Review the tags that comprise a form in html.

            HTML Form Basics
                HTML Forms are used to capture data that is input by the user. They nest input elements that users can enter information into. In order to be submittable, forms also need to nest an input or button with the type of "submit".  HTML forms can send HTTP requests when submitted if the "method" attribute is set to an HTTP verb and the "action" attribute is set. HTTP (hypertext transfer protocol) requests are the most common way for data to be transmitted through the web (https, in particular, which is the secure counterpart to http), and HTTP verbs specify the operation being attempted. If you're creating data, you typically send a request with the POST http verb. If you're retrieving data, you typically send a GET request. If you're updating data, you typically send a PATCH request (or a PUT request for a full replace). If you're deleting data, you typically send a DELETE request. Backend APIs create endpoints that handle requests mapped to these http verbs.

                

                With forms, you will usually send a POST request to your backend or to some third-party API (like the weather forecasting API you used during the Intro class, if you took that class) when submitting the form. You can also intercept the submission process on the frontend (before the request is sent to the intended target) using JavaScript. More about that later.

            HTML Form Elements
                Some important elements that nest inside forms include: 
                    <input></input> 	

                    Input: a single-line text box; The type attribute determines the datatype the user can input. If type="number" for example, the input element will not accept string characters. Inputs can have a "placeholder" attribute, whose value will appear in the text box before the user has typed anything in.
                    <label></label> 	

                    Label: a text label for an input; to keep an input and label grouped, set the for attribute of the label equal to the id of the input.
                    <textarea></textarea> 	

                    Textarea:  a way to submit paragraphs worth of text; can have a placeholder attribute.
                    <select></select> 	

                    Select: a dropdown input whose choices are specified with <option></option> elements, each of which has a value attribute that you can set. (The text between the options is what the user will see when selecting the option.)
                    <button></button> 	

                    Button: a button; type="submit" indicates that if this button is pressed, the form has been submitted.

        Classes in JavaScript Overview

            JavaScript, like C#, allows creating classes so that you can encapsulate state (properties) and behavior (methods) within a template. Here are some rules to keep in mind:

                Instance Members
                    Members are public by default, but can be made private by prepending the "#" character to the name of the member.
                    There is no "protected" keyword, but the convention is to prepend the names of members that are supposed to be internal with the "_" character.
                    Static members are accessed at the class level, and designated with the "static" keyword
                    Properties
                        Can have default values.
                        Are not bound to a particular type.
                        Can be defined in the body of the constructor using the "this." keyword without having to define them outside the constructor.
                        Can have simplified getters using the "get " keyword that eliminate having to call the getter with "()".
                    Methods
                        Do not use the function keyword
                        Do not specify types for their parameters or for what they return.
                        Can have default values for parameters, but they should be listed last after parameters that do not have default values
                Inheritance
                    Inheritance is specified with the "extend" keyword, and methods can be overridden.
                    Inherited methods can invoke the parent method of the same name using the "super" keyword.
                    Methods cannot be overloaded- JavaScript will simply execute whichever method of the same name is defined last (overwriting the previous ones);  default parameters can be a workaround for overloading though.
                    Constructors can call the parent constructor using super(), but this should be done before you use the "this" keyword to access the current instance of the class.

This API is called the Document Interface. When the webpage is loaded, JavaScript instantiates an instance of this interface using the root <html> tag of the DOM tree, creating the  document object. We can then invoke the following methods of the Document Interface on the document object to select HTML elements on the webpage:

                Document.querySelectorAll()
                    document.querySelectorAll("p") //returns all p elements in the document
                    document.querySelectorAll("ul li") //returns all li elements that hat are inside any ul elements

                    If there are no matches, returns something similar to an empty array.
                Document.getElementById()
                    document.getElementById("todo-list") //returns the element with the id "todo-list"

                Document.getElementsByClassName()

        A Brief Introduction to Event Listeners

            Think of a doorbell. When someone presses it (an event), a bell rings inside the house (an action is executed). Event 
            listeners work similarly in the digital realm. Event listeners patiently "wait" for specific user actions or "events" and 
            respond by executing specified functions or behaviors. 

            Event listeners enable interactivity and can add dynamic behavior to sites. Multiple event listeners can be added to any particular html element. If you want, you can also detect events on the entire page.

                Interactivity: By responding to user behaviors, web pages become more engaging.
                Dynamic Behavior: Web content can adapt in real-time, based on user actions or based on scheduled actions (using setInterval or setTimeout).

        Implementing Event Listeners

            Html elements have attributes for events whose values can be JavaScript written in a single string. For example, if you have written a handleClickOnButton between your <style> tags, you can make that function execute when a button is clicked as follows:

            <button onclick="handleClickOnButton()">Click me</button>

            

            However, it is best practice in modern web development to "separate your concerns" by adding potentially multiple event listeners to html elements in the JavaScript code itself:

            let btnElement = document.getElementById("myButton"); 

            btnElement.addEventListener("click", function() { 
            btnElement.textContent = "You clicked me!"; 
            });

            Here, a button's text changes upon a click, showcasing simple DOM manipulation.

            Exploring Event Types

            Numerous events can be detected and responded to:

            click: Triggered when an element is clicked.

            btnElement.addEventListener("click", function() { 
            document.body.style.backgroundColor = "lightblue"; 
            });

            

            mouseover: Fires when the mouse hovers over an element.

            let imgElement = document.getElementById("imageID"); 
            imgElement.addEventListener("mouseover", function() { 
            imgElement.src = "new-image-source.jpg"; 
            });

            

            keydown: Activated upon pressing a keyboard key.

            document.addEventListener("keydown", function(event) { 
                    if(event.key === "r") { 
                        document.body.style.backgroundColor = "red"; 
                    } 
            });

            

            submit: Detected when a form is submitted.

            let formElement = document.getElementById("signupForm"); 
            formElement.addEventListener("submit", function(e) { 
                    e.preventDefault(); // Prevents actual form submission 
                    alert("Form submitted!"); 
            });

            The Power of Event Listeners

            Event listeners can be helpful in a few key ways.

                Enhanced User Engagement: Web elements come to life, responding to user interactions.
                Dynamic Content Generation: Based on actions, content can be added, removed, or modified.
                Instant Feedback: Validate form inputs on-the-fly, giving users immediate feedback.

            Detaching Event Listeners

            To cease listening for an event, the removeEventListener method is useful.

            function changeText() { 
            btnElement.textContent = "Once clicked!"; 
            btnElement.removeEventListener("click", changeText); 
            } 

            btnElement.addEventListener("click", changeText);

            Here, after one button click and text change, the listener detaches, preventing further changes.

            Common Questions & Best Practices
            Common Questions

                Can multiple event listeners be added to one element?
                    Yes, an element can have multiple listeners, even for the same event (which is not typical).
                Why pick addEventListener over HTML events?
                    Separation of concerns is highly valued in modern web development because you decouple possible areas of failure. Also, having your JavaScript be written in a string as the value for an HTML attribute is not ideal. Ultimately, both approaches can be used, but HTML events will be listened for first.
                Can I detect events on the entire page?
                    Absolutely! Use document or window as your target to detect broader events.

            Best Practices

                Descriptive Functions: Use self-explanatory names for functions, e.g., handleImageHover() over funcX().
                Event Delegation: Instead of listeners on many similar elements, delegate by targeting their shared parent.
                Optimization: Excessive event listeners can affect performance. Always optimize for larger applications.
                Event Capturing or Bubbling: If nested elements listen for the same event, consider whether or not you want the elements to listen in order of descending scope ("capturing") or ascending scope ("bubbling up").
                CSS Delegation: It's possible to apply CSS styles when the user hovers over an element using just CSS. Consider whether or not your logic is complex enough to warrant a JavaScript event listener instead of a simple CSS pseudo-class.

        Storing Data on Browsers
            Think back to when we created that question and answer section for our ecommerce site. That array of question-answer objects could be thought of as an "in-memory" database. However, we are at the point where we want to persist user data. If we were to add user data to such an in-memory database, it would be lost whenever the application restarts (in this case, whenever our page is refreshed). Modern browsers provide methods of storing such data after page reloads and even after the user closes the browser. In future, you will store user data in a database via a backend, but for now we will focus on frontend options only. SessionStorage stores information until its tab or the browser is closed. LocalStorage stores information until that information is explicitly deleted. Cookies are deleted when the browser closes, or after a specified duration of seconds.

            

            SessionStorage, LocalStorage and cookies all store data as text though, which means that in order to store complex objects therein we first need to serialize them into text using JSON (JavaScript Object Notation).         Dao pattern
            DAO Pattern Overview
                When developing applications, the logic required to furnish your desired functionality can get quite complex. A design principle called "separation of concerns" aims to make code easier to understand and test in isolation by "decoupling" functionality. For example, accessing stored data and using that data are two different concerns that are best handled separately (via a persistence/data-access layer and a business/application layer, respectively). The DAO (Database Access Object) Pattern is a design pattern that separates concerns into a data-access and business layers using classes and interfaces. Javascript does not have a concept of interfaces, but we can simulate interfaces using inheritance. Ultimately, we will use this pattern so that we can switch seamlessly between storing data using cookies or SessionStorage.

                In this assignment, you will:

                    Simulate interfaces.
                    Separate concerns.
                    Serialize and persist data as JSON.
                    Deserialize JSON data.
            
            DAO Pattern
                The logic for interacting with SessionStorage and LocalStorage is virtually the same, but it's very different for cookies. So what if you needed to change your approach mid-development to switch from using SessionStorage to using cookies, for example? If you haven't decoupled your business logic from your data-access logic, you will have a mess on your hands. Leveraging the DAO Pattern makes such a switch rather seamless. 

                The DAO pattern includes the following:

                    models: classes whose instances represent data that is to be retrieved from or saved to the datastore
                    one interface per model to describe what behavior is expected of any class that presumes to access or change data in models
                    data access object classes that implement such an interface
                    a service class that invokes the functions encapsulated within data access objects

                JavaScript does not have a concept of interfaces (unless you use Typescript), but we can simulate interfaces with inheritance by throwing errors if child classes do not override methods in the parent class.

                In the code-along for this module, we will represent products made by sellers (our users) as instances of a Product model. A ProductDAO will create a contract for creating a product and retrieving all products. We'll also create a CookieProductDAO and a SessionStorageProductDAO, both of which will store and retrieve information about products, but in very different ways. We'll then create a CreateProductService class whose constructor will expect a ProductDAO, which can be either CookieProductDAO or a SessionStorageProductDAO (polymorphism). This service class won't care which implementation of ProductDAO we pass to it, because either will expose a create() method with the same return type and the same parameters (this is the interface's "contract"). On the fly, we can switch between providing an instance of CookieProductDAO or SessionStorageProductDAO to our instance of the CreateProductService. This service class will handle the business logic of creating a product by taking data entered into the form, and executing the .create() method exposed by its instance of the ProductDAO, passing in the data from the form as parameters. This business logic will reside in the .createProduct() method of the CreateProductService, which its instance will have access to. When listening for the "submit" event on our form, we will execute this .createProduct() method on our instance of the CreateProductService.

        CSS basics
            Module Overview - CSS Basics
                Now that we understand how to structure and give dynamism to websites, it's time to enhance the user experience even more by improving the site's appearance using CSS (cascading stylesheets). 

                In this module, you will:

                    Select HTML elements by their tag name, ID, and class name.
                    Combine CSS selectors.
                    Adjust the relative position of HTML elements using CSS.

            CSS Overview
                CSS is what confers visual appeal to the information your HTML is conveying. With enough familiarity with CSS, your webpage can go from looking dated and amateurish to looking polished and professional.

                In this page, you will:

                    Differentiate CSS selectors.
                    Explore CSS style rules.

                Applying CSS, or Cascading Style Sheets, is how you format and stylize html elements. CSS code consists of a series of rules that apply to identified html elements. CSS can live in one of three places: between style tags in the head of your html page (internal CSS), as the value for the "style" attribute of an html element (inline CSS), or in an external stylesheet that you link to in the <head> tag of a page (external CSS). The word "cascading" refers to how styles are applied to elements when there are conflicting instructions. If styles ever conflict, the style read last will ultimately be applied. For example, if you first link to an external stylesheet, then specify styles between style tags, and then specify styles for specific html elements, that is the order in which the styles will be applied, overriding in the case of conflicts.

                Among the three places where styles can be located, external style sheets are the most common in the industry. Here is an example of a stylesheet:

                body {
                font-family: Arial, Helvetica, sans-serif;
                background-color: #888;
                color: #DDD;
                }

                .a-class {
                font-size: 36pt;
                color: #DDF23A;
                }

                #that-one-element {
                font-size: 48pt;
                color: red;
                }

                Each block constitutes a "rule". The "selector" precedes the curly braces and specifies which elements the stylization will apply to. The body of the curly braces represents the rule's "declaration", and specifies values for css properties of the selected html elements.

            CSS Basics
               In this stylesheet, we apply one set of styles to the <body> tag, another to all elements whose class list includes "a-class", and another to the (only) element whose id attribute has a value of "that-one-element". We will explain what these mean below. Note that the value of the class attribute for an html element is a string, and that string can include multiple names separated by spaces . This means that every html element has a list of CSS classes that apply to it, even if that list is empty by default. Each class can be separately selected for in CSS rules. So, if an html element indeed has multiple class names included in the value for its class attribute, the CSS rule that selects each class name will be applied to that html element (in order, overriding in the case of conflicts).

                CSS can be used to control many different aspects of how an HTML element is rendered. For now, we'll discuss these basics:

                    Colors: The following CSS attributes let you control the color of elements and the text within them.
                        background-color: controls the overall color of the element.
                        color: controls the color of text in the element.
                    Fonts: These elements control various aspects of text within elements
                        font-family: controls which type of fonts are used. Common font families include serif, sans-serif, and monospace.
                        font-size: controls how large text is in an element. Can be specified in pixels - px, points pt, or em - em. Em allows for resizing of text by users and/or for responsive design.
                        font-weight: normal or bold.
                        font-style: normal or italic

            CSS Selectors
              CSS Selectors are a set of tools for specifying which element or elements a given style should be applied to. Selectors can be used to identify a specific element, or to select elements by tag type, CSS class, ordering on the page, nesting within other elements, or various other methods and combinations. For this course, you'll want to understand these:

                    #: the hash symbol allows us to specify an element on the page by its id. For instance, #page-header would select an element with the attribute id="page-header'
                    .: the dot symbol allows us to select a set of elements by CSS class. Classes are simply a CSS tool that lets us set up groupings of elements for styling purposes. For instance, we might add the attribute class="external-link" to <a> tags that link to sites outside of our own. A class selector for this would look like .external-link
                    tag: we can select elements of a given tag type by simply using the name of that tag, IE p for all paragraph <p> elements.

                So in our stylesheet example above, we select the <body> element for one style, all elements whose class list includes "a-class" for another, and the element whose id attribute has the value "that-one-element" for the third.

                

                We can also select descendent HTML elements like so:

                body div[name="main-container"] div.sub-container ul li {
                    color: green;
                }

                This would select all list items inside every list inside every div that has the class sub-container inside the div with the name main-container.

                

                If you were to name this stylesheet index.css and place it in the same directory as our index.html, you would load the stylesheet by linking to it in the head of your html like so:

                <html>
                    <head>
                            <link rel="stylesheet" href="./index.css">
                    </head>
                    <body>
                            ...
                    </body>
                </html>

            A Brief Introduction to Tailwind
                Tailwind CSS is a CSS framework that uses "utility classes" to style HTML elements directly. Read the utility-first section of the docs to learn more about these utility classes and to see them in action. 

                Like Vite, Tailwind is an npm package, so we'll have to install it using npm install -D tailwindcss. Tailwind also has a tailwind.config.js file we can generate by running npx tailwindcss init. In this file, we can specify the locations of files and the extensions of our template files (files that will contain Tailwind utility class names). 

                Additionally, we add three Tailwind directives to our main CSS file: @tailwind base; @tailwind components; @tailwind utilities;

            Running a CLI Tool
                We can run a CLI tool to scan the template files we specified in tailwind.config.js and compile those utility files into actual CSS code in a specified destination folder: npx tailwindcss -i ./src/input.css -o ./src/output.css --watch

                In the above example, input.css is where we put our Tailwind directives, and output.css is where our compiled CSS will be stored. The watch flag tells Tailwind to continuously build the CSS as the utility files are edited in the template files.
